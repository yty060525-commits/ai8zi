# F5: 流年流月公历年月推导、边界案例、开源实现对照，以及如何为规则冲突建立可执行测试。

## Findings

### [1] 流年、流月不能把公历月号直接当作干支月；实现应先以节气时刻把输入瞬间分段，再映射到月支序列。
- quote: "支持...节气...八字、五行、十神"
- url: https://github.com/6tail/lunar-python
- source_type: community
- published: unknown
- confidence: medium

### [2] `lunar-python`提供了可复用的公历输入、节气和八字接口，适合作为程序的历法基准而不是把节气日期写死在业务代码中；其文档还列出“阴历年节气表”API。
- quote: "无第三方依赖的公历(阳历)、农历(阴历)...工具库"
- url: https://6tail.cn/calendar/api.html
- source_type: community
- published: unknown
- confidence: high

### [3] 开源排盘实现明确以带时分秒的公历时间创建 Solar 对象，并同时查询前后节气，这说明边界判定必须保留时间而非只保留公历年月日。
- quote: "Solar.fromYmdHms(int(options.year), int(options.month), int(options.day), int(options.time), 0, 0)"
- url: https://raw.githubusercontent.com/china-testing/bazi/master/bazi.py
- source_type: community
- published: 2019-02-21 (文件头声明)
- confidence: high

### [4] 该实现把前一个和下一个节气的完整时间打印出来，并由 `getYun` 计算起运，因而可作为回归对照样本；但它还混合了大量命理断语，不能把其所有输出当作规范真值。
- quote: "lunar.getPrevJieQi(True)...lunar.getNextJieQi(True)"
- url: https://raw.githubusercontent.com/china-testing/bazi/master/bazi.py
- source_type: community
- published: 2019-02-21 (文件头声明)
- confidence: medium

### [5] `sxtwl_cpp`的公开 Python 构建项目只负责把 C++ 库打成 Windows wheel，不是流年流月规则本身；采用它时应把“历法计算库版本”和“月柱映射规则”分层测试。
- quote: "利用appveyor自动打包 sxtwl_cpp 的python wheel for win"
- url: https://github.com/yuangu/sxtwl_cpp_python_builder
- source_type: community
- published: 2018-08-30 (仓库元数据)
- confidence: high

### [6] 公历流年应以目标瞬间所在的节气年定义，而不是无条件使用 `date.year`；至少必须覆盖元旦至立春、立春前后、以及跨午夜的节气边界。
- quote: "获取节气表"
- url: https://6tail.cn/calendar/api.html
- source_type: community
- published: unknown
- confidence: medium

### [7] 流月应按“本地化后的时间是否早于节气瞬间”作半开区间判定：`[term_i, term_{i+1})`归当前月，恰在节气时刻的样本必须固定为“已进入”或“未进入”之一，不能依赖浮点相等。
- quote: "Solar...获取年、月、日"
- url: https://6tail.cn/calendar/api.html
- source_type: community
- published: unknown
- confidence: medium

### [8] 可执行的冲突测试应把历法基准、时区、边界策略和期望干支作为表驱动字段；同一输入分别送入候选实现，若结果不同则记录规则标识而不是静默覆盖。
- quote: "supports Solar and Chinese Lunar"
- url: https://raw.githubusercontent.com/6tail/lunar-python/master/README_EN.md
- source_type: community
- published: unknown
- confidence: medium

### [9] 最小回归集应包含闰年2月29日、年末跨年、立春前后、每个节气的前一秒/正点/后一秒，以及东八区与 UTC 跨日样本；断言应同时检查公历归属、节气区间和干支结果。
- quote: "convert to solar and print"
- url: https://raw.githubusercontent.com/6tail/lunar-python/master/README_EN.md
- source_type: community
- published: unknown
- confidence: medium

## Suggested follow-ups
- 获取同一年度、同一时区的香港天文台或天文历节气时刻表，建立 24 个节气的数值 golden tests。
- 对比 `lunar-python`、`sxtwl_cpp` 与一套独立天文历法，在立春/节气正点及历史时区变更日逐秒测试。
- 明确产品规范：采用立春还是正月初一作为流年切换点，并明确节气时刻的时区与等号归属。
