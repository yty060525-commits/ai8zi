## 任务编排

[baziOrchestrator.ts](../../client/src/data/baziOrchestrator.ts) 的关键约定：

- `buildBaziTasks(record)` 产出固定编号序列：`task-01` 本命；流年流月占 `task-02..task-23`；`task-30` 后天调整；大运段从下标 `FIRST_DECADE_TASK_INDEX = 24` 起排；`OVERVIEW_TASK_ID = 'task-31'` 全盘总结。编号即缓存语义，改顺序要升缓存键。
- `REQUIRED_SECTIONS`：每类任务正文必须出现的小节，缺了判脏重算。
- `FIXED_CONCURRENCY = { scope: 8, decade: 3, repair: 6 }` 与 `fixedMapLimit`：并发上限，防限流。
- `isRetryableFailure` / `isThrottleFailure` / `isRateLimited` / `isTimeoutFailure`：失败分类，决定自动重试还是停下。
- **重试按条记账，不按批**（缺陷 #108/#121）：`roundOf(taskId)` 给每条任务造一本 `TaskRound = { budget, repairBudget }`，
  主跑那本 `{ retriesLeft: retries }`（默认 `retries = 1`）由 step 的首发与池子的退队重发**共用**；补跑那本
  `{ retriesLeft: REPAIR_BUDGET = 1 }` 独立。全仓只有三处 `spend()`：池子退队、step 首发、补跑循环 ——
  「出门必扣、进门必看」，闸门排在扣账之前(反过来的话退队重发已把这本账扣光，一条都发不出)。
  恒失败盘因此是**每条两口子封顶**(首发 + 再试一口)，HEAD 旧写法是三口(#121 的超发)。
  代价如实记下：主跑额度被自己的首发扣光 ⇒「completed 但缺【小节】」不再在主跑内自动重写，而补跑名单只收 failed。
  实测整轮读数(23 条任务)：恒失败 retries:1 = 46 口，恒超时 retries:1 = 67 口，retries:0 = 67 口；
  对比 HEAD 的 69 / 90。判据在 [pool-retry-budget.test.ts](../../client/src/__tests__/pool-retry-budget.test.ts)。
- `sanitizeAnalysis` + `stripMarkers`：写入前清洗（去草稿标记、去非中文）。**这只是第一道**，展示与复制路径还要再兜一道。
- `collectFindings`：把已算时段要点压成 `AiFindings` 喂给总结任务，`FINDING_SNIPPET = 260` 控制长度。
- `analysisHorizon`：未来十年的窗口锚点，必须与详情页展示同源（跨年存量流年第 10 年无干支那次就是不同源导致的）。
- `DEFAULT_TONE = 80`：语气滑杆默认值。**五处**各自写着这个数字(baziOrchestrator 的常量、deepseekAdapter 与 chatEngine 的兜底表达式、server/ai.mjs 的同名常量、桌面 `clamp_tone` 的 None 分支)，由 [tone-default-single-source.test.ts](../../client/src/__tests__/tone-default-single-source.test.ts) 逐处读源码字节比对(#129)。改这个数要五处一起改，否则界面文案与模型收到的语气要求会分叉。

## 通道选择

[deepseekAdapter.ts](../../client/src/data/deepseekAdapter.ts) 的优先级：**服务器 → 桌面 Tauri → 浏览器直连**。

- 服务器模式判定只看 `isServerMode()`（有地址且有会话），见 [serverClient.ts](../../client/src/data/serverClient.ts) 第 22 行。
- 桌面通道经 `invoke('run_ai_task')`，会话启停是 `begin_ai_session` / `cancel_ai_session`。
- 浏览器直连自己拼请求体，其中 Qwen 会打 `cache_control` 显式缓存标记，够最小可缓存前缀才打标 —— 短请求打了只会白付建缓存费。
- 备用通道的尝试顺序由 `channelOrder()`（第 153 行）给出：**当前使用通道 → 其余已配置通道**，首选值读 `localStorage['mingli.provider']`、缺省 `qwen`。这条读点与服务器/桌面同源：服务端 `providerOrder(db, preferred)` 用客户端传来的 `provider`，桌面 `provider_order(&selected_provider())` 读 keyring 里那份选择。判据见 [provider-follow-contract.test.ts](../../client/src/__tests__/provider-follow-contract.test.ts)「浏览器直连的通道顺序与设置页读同一个键」—— 它钉的是「整份 adapter 里这个键只出现一次」，所以有人新写第二份偏好来源(比如按盘存)就会撞红；实测把键换成 `'mingli.channel'` 该条立即红(#137)。
- `configureAiTaskRunner` 允许测试注入 runner，生产不用。
- 错误文案统一出口：`readableTransportError`、`classifyFailure`，页面拿到的必须是中文可读串。

提示词常量在这一份里也有：`SCOPE_PREFIX`、`BASELINE_PREFIX`、`OVERVIEW_PREFIX`、`ADJUST_PREFIX`、`OUTPUT_RULES_TEXT`、`NATAL_BLOCK_HEAD`、`TONE_HEAD`、`INSTRUCTION_TAIL_MARK`、`NATAL_SHARED_KEYS`、`buildPromptSharedSeams`。**这三端各一份的同源关系由两份 parity 测试把守**，详见 [13-跨端共享与三端一致性](./13-跨端共享与三端一致性.md#提示词同源)。

## 聊天

[chatEngine.ts](../../client/src/data/chatEngine.ts) 的做法是「先检索、后作答」：提问解析成检索计划（人名 / 今年明年 / 本月下月 / 健康·事业·财运·爱情·五行等主题），从库里取证（命盘事实 + 已算流年流月大运本命批断，缺段按缓存键补读 `ai_cache`），让模型只依据证据回答，首轮答案落缓存复用。服务器存储是瘦身版，所以聊天请求会随带本机引擎现算的时段干支行补齐。

⚠ 落本机只有两种明确情形，**云端答完之后不许再悄悄换通道**（#136）：一是服务器不可达（`ServerError` status 0），二是服务器自身报错且浏览器里配了本机凭据。第三种曾存在的分支——服务器返回 `completed` 但正文没过纯中文闸门 → 用浏览器密钥重答——已删除：服务端 `chat.mjs` 自己就用同一份 `chineseGate` 洗过一遍，洗净为空即换 provider、全失败返回 `failed`，所以那条路正常根本走不到；即便走到，连着服务器却用另一把密钥重答，用户也看不出回答出自哪条通道。现在这种情况就地返回 `failed` 并给出「云端返回的正文不是纯中文，已拦下未展示」。判据在 [chat-engine.test.ts](../../client/src/__tests__/chat-engine.test.ts) 的「askChat 通道分流」，夹具必须选一句**不含任何已登记字段名**的脏串（含 `favorable`/`chart`/`element` 的句子会被 `FIELD_NAME_ZH` 翻成中文而洗成非空，等于没测）。

⚠ 上面第二种情形里「本机一条凭据都没配」这一支报的是 `not_configured`，但文案必须先说清**服务器那边答不上来**（带状态码读法，如「服务返回五零三」）再指方向 —— 用户早已填好服务器地址与账号，把一次服务端故障说成「你还没配凭据」会把人领去填一个对本轮不起作用的本机密钥。这条行为由「服务器报错且本机一条凭据都没配」那节判据钉住：它先正向证明三条 `mingli.cred.<id>` 确实是 `anyChannelConfigured()` 读的键（塞进去能被读到），再断言 `chatDirect` 未被调起、报错串含「服务器」与「五零三」且整句能过闸门上屏(#137)。

同一个文件还导出 `readableName`：纯中文名原样显示，含拉丁字母或数字的旧名逐位读成中文，空名回落「未命名」，原始串由调用方放进 `title`。它同时用于账号名与命主姓名，是存量脏数据的读时兜底。

## 存储门面

[clientRepository.ts](../../client/src/data/clientRepository.ts) 把「本机有没有桌面库」「有没有登录服务器」两种差异收在一个接口后面：

- 读写：`saveBaziRecord` / `listBaziRecords` / `getBaziRecord` / `deleteBaziRecord` / `refreshRecord` / `hydrateRecord`。
- 同步：`unsyncedRecordIds`、`syncAdminAll`、`markKnownRemote`、`flushPendingPruneWrites`。
- 剪枝：`pruneRecord`、`pruneStaleTasks`、`repairElementCounts`（旧库五行口径变更后的修复）。
- 指纹：`fpOf` = 性别 + 四柱 + 出生年月，导入去重用；缺出生月会误删他人记录，别动这个键序。
- 测试钩子：`initializeMockSession`、`resetMockSession`、`memoryBaziRepository`、`configureBaziRepository`、`__assumeOnServerForTests`、`__failRemoteForTests`。

**读取回写会把并发写入冲掉**（手机上表现为「进度不结束、旧套话不走」），任何「读一遍再整体写回」的代码都要带旁路计数判据，见 [51-测试矩阵](./51-测试矩阵.md)。
