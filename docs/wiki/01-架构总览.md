# 01 架构总览

一个仓库、三种形态、同一套命理引擎：**Web PWA**（GitHub Pages）、**Windows 桌面**（Tauri 2）、**Linux 中继服务器**（Node 零依赖）。三端共用 [client/src/types/domain.ts](../../client/src/types/domain.ts) 定义的记录结构，共用一份中文闸门，共用同一套提示词口径。

## 分层职责

| 层 | 位置 | 只做什么 | 绝不做 |
| --- | --- | --- | --- |
| 界面层 | [client/src/features](../../client/src/features) | 收输入、渲染事实与批断、把动作交给数据层 | 直接算干支、直接发 AI 请求 |
| 编排层 | [client/src/data/baziOrchestrator.ts](../../client/src/data/baziOrchestrator.ts) | 拆任务、并发、重试、清洗、进度 | 决定走哪条通道 |
| 通道层 | [client/src/data/deepseekAdapter.ts](../../client/src/data/deepseekAdapter.ts)、[chatEngine.ts](../../client/src/data/chatEngine.ts) | 服务器 / 桌面 / 浏览器直连三选一与降级 | 改任务语义 |
| 存储层 | [clientRepository.ts](../../client/src/data/clientRepository.ts)、[offlineSql.ts](../../client/src/data/offlineSql.ts)、[server/db.mjs](../../server/db.mjs)、[lib.rs](../../client/src-tauri/src/lib.rs) | 记录与缓存的读写、同步 | 参与命理判断 |
| 计算层 | [nonAiCalculator.ts](../../client/src/features/chart/nonAiCalculator.ts)、[shenSha.ts](../../client/src/features/chart/shenSha.ts)、[elements.ts](../../client/src/features/chart/elements.ts) | 确定性事实：四柱/五行/十神/神煞/大运/称骨 | 调模型 |

## 一次「批断分析」的完整链路

1. [PersonDetail.tsx](../../client/src/features/person/PersonDetail.tsx) 点「批断分析」→ 调 `buildBaziTasks(record)`。
2. [baziOrchestrator.ts](../../client/src/data/baziOrchestrator.ts) 产出任务序列：`task-01` 本命、流年流月占 `task-02..task-23`、`task-30` 后天调整、大运段从第 24 位往后、`task-31` 全盘总结（常量见该文件 `FIRST_DECADE_TASK_INDEX`、`OVERVIEW_TASK_ID`）。
3. 每个任务交给通道层：服务器模式走 `runTaskOnServer`（[serverClient.ts](../../client/src/data/serverClient.ts)），否则 Tauri `run_ai_task`（[lib.rs](../../client/src-tauri/src/lib.rs)），再否则浏览器直连（[deepseekAdapter.ts](../../client/src/data/deepseekAdapter.ts)）。
4. 通道内部先查缓存键，命中即返回；未命中才花钱。缓存键三端各有一份实现，必须同步演进 —— 见 [13-跨端共享与三端一致性](./13-跨端共享与三端一致性.md#缓存键)。
5. 结果回写 `record.aiTasks`，经 `sanitizeAnalysis` 清洗后落库；展示与复制路径读取时再过一遍清洗。存量数据不会自动变干净这件事，写在 [13](./13-跨端共享与三端一致性.md) 末尾。

## 一次「问问 AI」聊天的链路

入口在排盘页 [ChartChat.tsx](../../client/src/features/chart/ChartChat.tsx)，核心是 [chatEngine.ts](../../client/src/data/chatEngine.ts)：提问先解析成检索计划，再从库里取证（命盘事实 + 已算时段批断，缺段按缓存键补读），最后让模型只依据证据作答。服务器侧对应 [server/chat.mjs](../../server/chat.mjs) 的 `/api/chat`；断网落 Tauri `run_ai_chat`；再不行走浏览器直连。细节见 [12-客户端-数据层](./12-客户端-数据层.md#聊天) 与 [21-服务器端](./21-服务器端.md)。

## 数据落在哪里

- 桌面：exe 同目录 `data\bazi_records.sqlite3`，表结构见 [22-桌面端-tauri](./22-桌面端-tauri.md#schema)。
- 服务器：SQLite（`node:sqlite`），表 `users / sessions / records / settings / ai_cache`，见 [server/db.mjs](../../server/db.mjs) 与 [21-服务器端](./21-服务器端.md#schema)。
- 网页离线镜像：sql.js 数据库字节存 IndexedDB（[offlineSql.ts](../../client/src/data/offlineSql.ts)），密钥存 localStorage（[aiSettings.ts](../../client/src/data/aiSettings.ts)）。

## 发布链路

提交 → `npm run build`（构建时注入 git 版本号与时间戳构建号）→ `node scripts/deploy-pages2.mjs` 把 `client/dist` 推到 gh-pages → Pages CDN 生效约需 30–90 秒。为什么必须在提交之后构建、旧哈希 chunk 为什么不能全删，都写在 [41-构建与发布](./41-构建与发布.md)。
