# 42 工具脚本

位置：[scripts](../../scripts)。都不参与运行时，只在开发机上跑。分三类：发布与生成(deploy-pages2.mjs、gen-true-solar.mjs、version.sh)、度量与排查(measure.mjs、read-vitest-json.cjs、scan-localstorage-keys.cjs)、判据电池(beijing-caliber-scan.cjs、check-wiki-links.cjs 与十一套 mutation-*.cjs)。

⚠ 本节的脚本清单由 `wiki-links-reachable.test.ts` 逐文件名校验：新增脚本必须在这里登记，否则用例红。上一版这里只写了发布类脚本，漏掉十几个判据与排查工具 —— 散文里的数量词没人回去改就长期说谎，所以判据钉的是**完整性**而不是具体数字，本文也刻意不再用数量词声称个数。

## deploy-pages2.mjs —— 发布到 gh-pages

[scripts/deploy-pages2.mjs](../../scripts/deploy-pages2.mjs)：把 `client/dist` 经 GitHub Git Data API 推到 `gh-pages` 分支（blob → tree → commit → `PATCH refs/heads/gh-pages`）。仓库固定为 `yty060525-commits/ai8zi`，令牌取 `GH_TOKEN`，缺省回退读 `.git/config` 里的 token。

用法与两条铁律见 [41-构建与发布](./41-构建与发布.md)：parent 必须指向 gh-pages 自身；旧哈希 chunk 每个基名只留最近 `KEEP_PER_BASE = 3` 份，全删会让线上旧页面动态 import 404。

## gen-true-solar.mjs —— 生成真太阳时经纬度树

```bash
NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7897 node scripts/gen-true-solar.mjs
```

抓 DataV 行政区划 GeoJSON（`https://geo.datav.aliyun.com/areas_v3/bound`）的质心，拼成「省 → 市 → 区」经度树，单行压缩写入 [client/src/features/chart/trueSolarData.generated.json](../../client/src/features/chart/trueSolarData.generated.json)（已入库、懒加载），并打印省市区数量与字节数。直辖市标记 `municipality: true`，其二级即区、不再挂三级 —— 这个形状由前端消费方约定，改脚本要同步看 [11-客户端-特性层](./11-客户端-特性层.md) 的真太阳时一节。并发 8、失败重试 3 次。

排盘侧当前**只取经度差**做真太阳时修正，均时差不参与；权威口径判据在 [true-solar-authoritative.test.ts](../../client/src/__tests__/true-solar-authoritative.test.ts)。

## measure.mjs —— 提示词 token 度量

以 **readOnly** 打开桌面本机库 `data\bazi_records.sqlite3` 里一条已完成批断的记录，import 服务器端的 `buildTaskPayload`（[server/ai.mjs](../../server/ai.mjs)），按编排器顺序逐任务统计字符数：中文按 0.7 token/字、ASCII 除以 4 估算输入 tokens，再从 `aiTasks` 正文统计输出。用途是判断某段前缀够不够 Qwen 的最小可缓存门槛（约 1024 token），见 [13-跨端共享与三端一致性](./13-跨端共享与三端一致性.md)。

注意路径写死在脚本第 2 行，换机器要改；它只读不写数据库。

## version.sh —— 版本快照与回退

```bash
./scripts/version.sh show              # 当前版本、最近快照、如何回退
./scripts/version.sh save <说明>       # git archive 存快照 + 打 tag
./scripts/version.sh list              # 列出所有快照
./scripts/version.sh restore <快照名>  # 恢复到工作区（不碰数据）
```

版本号 = `rev-list --count HEAD` + `rev-parse --short HEAD`，与 [client/vite.config.ts](../../client/vite.config.ts) 注入 UI 的构建戳同源，所以线上看到的「第六版，校验码……」能直接对上快照名去回退。

为什么两套并存：本仓库工作区常有其他会话未提交的改动，单靠 `checkout` 容易连带丢掉别人的进行中工作；`key-backups/snapshots/*.tar.gz` 用 `git archive` 只存 HEAD 跟踪的文件，不含 `node_modules` / `dist` / `target`，也不含 `server/data`。恢复时解到独立目录再对比拷贝，绝不做整目录覆盖式删除。

## 度量与排查

[read-vitest-json.cjs](../../scripts/read-vitest-json.cjs)：读 vitest 的 JSON reporter 产物，逐文件打印用例状态与失败信息。存在的理由是**汇总行带 ANSI 转义**，按纯文本写的正则会永远匹配不到 `failed`；这个脚本先把 `\u001b[…m` 剥掉再解析。默认读 `bj.json`，可传路径。用完请删临时 json，别留在工作区。

[scan-localstorage-keys.cjs](../../scripts/scan-localstorage-keys.cjs)：枚举测试里出现过的 `localStorage.getItem/setItem/removeItem` 键字面量，用来判断「线上扫到脏串」到底是产品写入还是测试数据残留在本机存储。注意它把仓库根路径写死在开头，换机器要改。
