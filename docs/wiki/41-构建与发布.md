# 41 构建与发布

三套产物、一条纪律：**先提交，再构建**。因为构建会把 git 版本号烧进产物，先构建后提交会让线上显示的版本落后一次。

## 前端构建链

配置：[client/vite.config.ts](../../client/vite.config.ts)

- `BUILD_ID = String(Date.now())` —— 当次构建时间戳。
- `gitVersion()` 取 `rev-list --count HEAD` + `rev-parse --short HEAD`，形如 `6-caa86bd`；非仓库或无 HEAD 时为空串。
- 两者经 `define` 注入为全局常量 `__BUILD_ID__` / `__GIT_VERSION__`，消费方是 [client/src/utils/buildInfo.ts](../../client/src/utils/buildInfo.ts)。
- `buildStamp()` 插件在 `closeBundle` 阶段把 `dist/sw.js` 里的 `__BUILD_ID__` 占位符替换成真实时间戳；**找不到占位符直接抛错**，防止缓存永不失效的发版事故。
- 测试配置也在这里：`environment: 'jsdom'`、`include: src/__tests__/**`、`setupFiles: ./src/test-setup/netGuard.ts`（网络闸口）。

命令：`npm run build` = `tsc -b && vite build`（类型检查不过就不出产物），产物在 `client/dist`。

## Service Worker 与版本号

[client/public/sw.js](../../client/public/sw.js)：

- `const CACHE = 'mingli-__BUILD_ID__'`。**CACHE 若写死常量，已装 PWA 的手机永远停在旧版**（静态资源缓存优先，命中就不联网）。
- `install` 里 `skipWaiting()`，`activate` 里删掉所有非当前缓存并 `clients.claim()` → 在线刷新即取新版。
- 导航请求与 `index.html` 走**网络优先**，且必须带 `cache: 'no-store'`：GitHub Pages 给 index.html 也发 `max-age=600`（见 [sw.js](../../client/public/sw.js) 注释），默认的 fetch 会吃这份 HTTP 缓存，让「网络优先」取回的仍是旧页面。
- 同源 `/api/` 请求**一律放行不碰**：被缓存优先命中会拿到旧回包，网络失败又会被兜到 index.html，前端把 HTML 当 JSON 解析。

界面上的版本展示同样走中文口径（`buildLabel` 读成「二零二六年十月四日十九时五分」、`cnVersion` 读成「第六版，校验码……」），机器标识原串留在 `title` 里供核对。底部常驻版本号的意义见 [51-测试矩阵](./51-测试矩阵.md) 的构建戳用例。

## Web 发布（GitHub Pages）

```bash
# 1. 提交改动
# 2. 构建（必须在提交之后）
cd client && npm run build
# 3. 发布：仓库根执行
GH_TOKEN=<令牌> node scripts/deploy-pages2.mjs
```

令牌取自 git 凭据管理器，注意切分方式：

```bash
git credential fill <<< $'protocol=https\nhost=github.com' | grep '^password=' | cut -d= -f2-
```

用 `-f2` 会把含 `=` 的令牌截断。github.com 从本机 CLI 不可直连，需要 `HTTPS_PROXY=http://127.0.0.1:7897` 前缀。

[scripts/deploy-pages2.mjs](../../scripts/deploy-pages2.mjs) 的做法与两条铁律：

1. 走 Git Data API 把 `client/dist` 写成 blob/tree/commit，`PATCH refs/heads/gh-pages` 时 **parent 必须是 gh-pages 自己的上一个提交**；写成 main 会让分支祖先链断成源码快照。
2. 旧哈希 chunk **不能全删**：线上还开着的旧页面动态 import 会 404；也不能全留：曾堆到 206 个文件 / 41MB。策略是每个基名只保留最近 `KEEP_PER_BASE = 3` 份（即大约上一版）。别用「按构建时间判龄」来清理，本项目里那个判据恒为 0 条。

Pages 构建 + CDN 生效约 30–90 秒，发布后要轮询状态再去浏览器验证。站点地址 https://yty060525-commits.github.io/ai8zi/。

PWA 包同步：重大更新后把 `client/dist/*` 压缩覆盖 `release/pwa/dist.zip`。

## 桌面发布

`client\build-windows.cmd`（自动 `npm ci` → 前端 → `tauri build`，增量约 1–3 分钟），产物 `release\windows\命理客户端.exe`（免安装）与 `命理客户端-安装版.exe`（NSIS，装到 `%LOCALAPPDATA%\命理客户端\`，其 exe 同目录同样生成 `data\`）。也可用云构建：`.github/workflows/build-windows-exe.yml`。编译中间件默认落在项目外 `%LOCALAPPDATA%\mingli-client-target`；日常双击 `清理体积.cmd`。细节见 [22-桌面端-tauri](./22-桌面端-tauri.md)。

## 服务器发布

零依赖 Node（≥ 22.5），`PORT=8787 node server.mjs` + systemd，见 [server/README.md](../../server/README.md) 与 [21-服务器端](./21-服务器端.md)。**`server/data/*.sqlite3` 是真实用户数据，部署脚本不得覆盖。**

## 回退

[scripts/version.sh](../../scripts/version.sh) 提供两套并存：`git tag` 是逻辑回退点（前提是工作区干净），`key-backups/snapshots/*.tar.gz` 是物理快照（`git archive` 只存 HEAD 跟踪的文件，避免连带丢掉其他会话的进行中改动）。用法见 [42-工具脚本](./42-工具脚本.md)。
