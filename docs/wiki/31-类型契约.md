## NonAiChart 里几个「口径注释」必须读

- `birthDay?`：真实出生的公历日。按生日自动排盘时写入，配合早子时换日 —— 23 点后日柱进一日，但命主实际仍生在当日，重算/换设备要用它把公历农历与起运锚回当天。手录四柱路径无此栏。
- `birthTime?`：可选原始北京时间 `{year, month, day, hour, minute}`，指农历转换后、真太阳时经度修正前的民用时刻。它用于精确判年/月节气与起运；与修正后 `birthDay` 可跨日期。旧盘缺时分时继续按 12:30 近似，不能从四柱恢复。人工修改任一柱会清除它，无变化保留；非法元数据不应作为精确时刻使用。服务器与 Rust 从 `nonAiResult.birthTime` JSON 路径读取，不新增数据库列。
- `elementRuleVersion?`：五行计数口径版本（当前 `branch-main-v2`，地支本气取藏干首位）。老库缺标记时按当前口径回填，见 `repairElementCounts`。
- `luckStart` / `luckOnset`：起运跨度与精确交运日。`luckOnset` 由出生时刻 + 跨度自算（3 日折 1 年、1 日折 4 个月），与库给的 `luckStart.date` 互为校核；大运按精确交运年排段，不对齐公历十年边界。
- `patternFacts` / `strengthScore`：引擎算定的格局与旺衰档位，**AI 必须沿用、不得另立或重判**。这两项加入时缓存键整体升过一次版本。
- `tiaohouFacts`：调候参考，辅助判据而非硬结论；只注入季节方向并标「参考」。
- `greatFortunes[].endYear`：大运段的真实结束年，窗口裁剪与标题都按它来。

新增本命事实字段的连带清单：三端 natal 拼装 + `NATAL_SHARED_KEYS` 顺序 + 两份 `FIELD_NAME_ZH` + 缓存键版本，见 [13-跨端共享与三端一致性](./13-跨端共享与三端一致性.md)。

## 聊天证据契约

共享小纯函数与类型位于 [chatRetrieval.ts](../../client/src/shared/chatRetrieval.ts)。`ChatSource` 记录来源种类、命主 id、可读标题、可选任务身份/年月、实际正文小节与来源端；只有真实非空且进入提示词的事实或批断才登记。`ChatEvidence` 在 chatEngine/server 内包含 plan、sources、missing；服务器旧响应仍允许不带 `evidence.sources`，客户端按可选字段兼容。`periodFactsContext` 绑定 recordId、所问年与可选月份，服务端核验目标与行日期后只接受白名单事实字段。来源元数据留在气泡展示状态，不作为 StoredMessage 历史发送。

## 非AI原位编辑契约

`types/domain.ts` 新增 `PillarKey/FiveElement/FortuneIndex/ManualNonAiFields/ManualNonAiEdits/NonAiEditRequest`。`manualEdits={version:1,fields}` 仅记录触碰叶子，四柱矩阵按year/month/day/hour，大运按原步序零至八；未出现的键保持自动，空数组表示人工清空。源姓名/性别/年月/四柱位于record顶层，真实birthDay仍只在nonAiResult。有效值同步原chart字段，不能只存展示字符串。

`NonAiChart` 的可选 `factsRevision`（旧盘零）用于防旧AI写入，`fortuneDirection` 为forward/backward，`zodiacCompatibility` 含sanHe/liuHe/chong/hai四组生肖。起运两日期别名、称骨totalLiang/totalText双向同步，重量范围零至九十九两九钱、精确到钱；无变化不增revision。新增三仓储API为 `saveNonAiEdits(id,request)`、`recalculateBaziRecord(id)`、`saveAiProgress(record,expectedRevision)`；失败抛中文错误、整次不保存。元数据与实际字段同在已有nonAi JSON内，Rust保存/压缩保留，无数据库迁移。

## 编码约定

1. **汉字作对象字面量的键必须加引号**（如 `{ '木': … }`），否则打包器按标识符处理会出错。
2. 面向用户可见的字符串不允许出现拉丁字母、阿拉伯数字与特殊符号；技术标识符只存在于代码与机器串（放 `title` 供核对），见 [13](./13-跨端共享与三端一致性.md)。
3. 类型改动先跑 `npx tsc -b`，再跑对应模块测试；三端序列化字段名以本文件为准。

## 本机规则结果的兼容字段

BaziTaskResult 保持 required status，仅追加可选 `source: 'cloud' | 'local'`；缺 source 的历史结果视为 cloud。BaziAIAnalysis 可选 engineVersion 仅用于本地结果的版本失效和续跑复用，云端不依赖它。source 和正文版本可以随结果同步；本机开通、启用、引擎清理及补算台账不进入 BaziRecord，也不扩展 AiProvider 或 ServiceId。精确交运日和当前任务窗口契约保持原样。
