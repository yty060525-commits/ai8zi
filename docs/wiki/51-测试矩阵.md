cd client/src-tauri && cargo test --lib                # 21 项
cd client && npx tsc -b                                # 类型检查（构建前置）

全量基线读数以 [账目登记表](../../client/src/__tests__/delivered-files-in-tree.test.ts) 的三条 GAPS 红为已知项：`Tests 3 failed | 713 passed (716)` —— 提交本人改动后单独复跑 `delivered-files-in-tree` 读到 `3 failed | 54 passed (57)`，即**只有那三条存量缺口红**。这两处是 2026-10-09 当场读数，比上一版记录(`710 passed (713)`/闸门 `53 passed (56)`)各多一条：#136 那条「云端正文没过纯中文闸门就地拦下、不得静默改走本机」的用例进了 `chat-engine`(该文件现 39 条)，同一句又登记进判据账本让闸门多一条。⚠ **全量总数会随他人未提交的 WIP 一起漂**：上一轮(#136 之后)全量实读 `3 failed | 712 passed (715)`，比当时表格声称的多出一条，逐文件核对后落在工作副本的 `auto-retry-schedule.test.tsx`(HEAD 5 条 → 工作副本 10 条)，不是本人改动。**#137 之后本轮全量实读 `3 failed | 714 passed (717)`**：本人这两条新判据各加一条(chat-engine 39→40、provider-follow-contract 4→5)，同样当场逐文件读数核对。别把这些当常量改来改去；要引用就读当场输出。**做减法前先确认两次读数取自同一条命令**：vitest 4.1.11 已删掉 `--reporter=basic`，传它会以 `ERR_LOAD_URL: Failed to load url basic` 直接退出、重定向文件里根本没有汇总行，拿它留下的旧计数当本次基线就会凭空造出「数字对不上」的谜题。**跑全量必须限并发**：`npx vitest run --pool=forks --maxWorkers=2`，默认并行在这台机器上会把十几个界面套件整批掐成 `Error: STACK_TRACE_ERROR`(runner 内部堆栈标记，不含真实断言)，单独跑同一文件必绿 —— 见到这种形态先怀疑 worker 耗尽，别去改判据。另有一类「慢机器全量并行时才冒出来」的超时假象(单独跑必绿)：纯计算/无同步检查点的用例若耗时贴着默认 `testTimeout 5000` 就会被掐死 —— `patternFacts`(专旺抽样)与 `decade-task-gate`(开跑补齐)已按实测各放宽到 30s，新写这类判据时记得给第三参。

[tauri-task-abort.test.ts](../../client/src/__tests__/tauri-task-abort.test.ts) 守 #142/#143（桌面本机通道接不住「立即停止」）。三条机制值得记住：① 桌面分支由 `window.__TAURI_INTERNALS__` 裁决，所以每条用例开头都要摆这个标记，并配一句**前提钉子**（没有标记时 `run_ai_task` 调用数必须为 0），否则整份文件会在走不到那条分支的情况下全绿空转；② 取消必须走真实导出 `cancelAiSession()`，桩按 Rust 的真实语义实现（会话置位后 `run_ai_task` 抛 `cancelled`），直接改桩里的布尔等于自证；③ 「先发后中止」与「中止后再发」是两条用例 —— 前者测不到 invoke 之前那句预检（变异 M4 因此在第一条里存活，补了第二条才杀掉）。同一份文件里还有一句服务器分支的取证途中预检判据，夹具用 `mingli.server.url` / `mingli.server.session` 摆登录态而不是替掉 `isServerMode`。

`auto-retry-schedule` 守的是详情页那套「整盘失败 → 十二秒后自动再跑」的调度器(`scheduleAutoRetry`)，此前全仓只在编排器层测过任务级重试，这个花钱的闸门无人读过。四条判据与三条取证值得记住：① **桩必须恒失败** —— 「首轮失败、之后成功」会被补跑轮(REPAIR_RETRIES)重跑成成功，整轮落 completed，`scheduleAutoRetry` 压根不触发；② 上限判据数的是 `analyzeBazi` 的**调用总数台阶**，不是最终状态，一轮 ≈ 队列 23 + 逐任务再试 + 补跑 ≈ 92 次、实测 ~16s，所以每条用例都要显式给第三参(45s–300s)；③ 「两次」是**每次手动批断**的额度(`if (!_auto) autoRetryCountRef.current = 0;`)，删掉这句后第二次手动失败会报「这是第二次」而不再排期 —— 要杀它得让第二轮仍落 failed，用「本轮前四分之三失败、尾部成功」的桩即可(首轮 49 次调用，第二轮复用缓存只发 3 次，调用数就是轮次边界)；④ 反向钉子：定时器回调必须以 `_auto=true` 调 `requestAnalysis(rec, true)`，写成手动形态会把额度清零变成无限重试，且界面永远显示「这是第一次」。变异 M1–M7(上限抬到三、删不可重试早退、取消不 `clearTimeout`、手动不重置额度、提示不写次数、自动轮当手动轮、额度耗尽不清 `autoWaiting`)全部有点名判据可杀。

文档链接判据的两条教训：

1. **锚点在标识符层面必须唯一**。像 `qwen-cache.test.mjs` 这种「显示文字与路径同名」的链接，
   文件名在一条链接里出现两次，整条做锚点再 replace 只改到**显示文字**、路径依旧有效，扫描器如实报「无坏链」，
   却被读成「判据杀不掉坏链」。落地断言因此要同时钉三条：新串在盘上、**旧串不在盘上**、命中数==1。
2. **冗余判据不留**。本判据第一次跑红就红在解释它的说明文字里（正文用了 `]()` 链接语法讲路径），
   当时想单加一道「省略号路径」闸门；实测发现 `path.normalize` 把 `…` 当普通目录名，任何含省略号的
   路径必然解析不到真实文件 ⇒ 存在性判据恒先抓到它，闸门删掉也不会少抓一条，遂删除。
   讲路径请用行内代码，不要用链接语法。

⚠ **进程内 Date 桩看不见「+8 小时再读 UTC 字段」这一族写法**（2026-10-04 实测）：
`class Stub extends Date` 改了本地 getter、保留 `getUTC*`，于是 `new Date(t+8h).getUTCMonth()`
里的 shifted 对象两条路给出同一个数，偏移被抵消 —— 加不加 8 小时都读出北京值。
用它写的用例只能钉「源码不许出现本地字段读法」和「行为回归」，**不能当作跨时区读数判据**。
读数级验证必须真换宿主时区(`spawnSync({env:{TZ:'America/New_York'}})`)，见
[tz-probe.test.mjs](../../server/test/tz-probe.test.mjs)。

预期存活是结论不是失败，须在名字里写明机制：
`?? 兜底`那一侧在真链路永不执行；上游时钟被下游等价补偿折回时不可观测。

## 验证纪律

- 汇总行先剥 ANSI 再解析：vitest 输出带 `\e[2m`，按纯文本写的正则会永远匹配不到 failed。
- 取真实退出码用 `${PIPESTATUS[0]}`，管道尾码不是被测进程的。
- 加新判据后做一次变异验证：把被测行为改掉，确认**只有该用的用例红**；杀不掉说明判据是摆设。
- 全仓并发跑偶有超时抖动（如 `patternFacts` 单跑 677ms 通过），别当成回归。
- 线上扫到脏串先分本机残留：源码与产物 grep 均无此串 ⇒ 是测试数据留在存储里，清 storage/SW/caches 重载再判。
