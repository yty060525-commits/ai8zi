位置：[client/src/features](../../client/src/features)、[client/src/components](../../client/src/components)、[client/src/App.tsx](../../client/src/App.tsx)。
本页两块内容：**四个页面**（只负责收输入与展示）和**排盘引擎**（本仓库唯一的事实来源）。

- [Modal.tsx](../../client/src/components/Modal.tsx)：弹层容器，被四柱手录弹窗复用。

## 排盘引擎（确定性计算，不调模型）

入口是 [nonAiCalculator.ts](../../client/src/features/chart/nonAiCalculator.ts)，页面用 `await import('./nonAiCalculator')` 动态加载（首屏不带重表，见 ChartPage 第 32、74、89、96 行）。

| 导出 | 作用 |
| --- | --- |
| `computePillarsFromDate` | 由公历日期算四柱 |
| `calculateNonAi` | 一次算全：四柱 / 五行 / 十神含藏干 / 纳音 / 十二长生 / 神煞 / 三合六合冲刑害破克 / 称骨 / 大运·流年·流月 |
| `applyTrueSolar`、`equationOfTimeMinutes` | 真太阳时修正。**当前口径只取经度差**，均时差函数保留但不参与排盘 |
| `lunarToSolar` | 农历（含闰月，负月表示）先转公历再排盘 |
| `singleCalendarMonth` | 某公历月的流月干支枚举 |
| `scoreStrength`、`derivePattern`、`deriveTiaohou`、`specialPatternHint` | 身强身弱评分、格局、调候参考（辅助判据，不是硬喜用） |
| `luRenOf`、`STEM_LU`、`YANG_REN` | 建禄、阳刃 |
| `LuckStart` | 起运（大运按精确交运年排段，不对齐公历十年边界） |

排盘时间链以输入的公历民用时刻为节气判定时刻：`computePillarsFromDate(input, { calendarTime })` 的 `calendarTime` 只控制年柱/月柱交节，未提供时用 `input` 自身时分；日柱仍按传入（可能已作真太阳时经度修正）的日期和现有子时换日开关计算。自动建盘把原始北京时间保存在 `NonAiChart.birthTime`，真太阳时目前仍只作经度差修正，修正后时刻供日柱与时柱使用。`calculateNonAi` 以原始民用时刻单独调用库的 `getYun`，起运跨度相加也锚在原民用日期；旧盘没有 `birthTime` 时沿用 12:30 近似，不能由四柱反推出原时分。手改任一柱后清除此元数据，无改动则保留。完整行为钉在[出生时刻精度回归](../../client/src/__tests__/chart-time-accuracy.test.ts)。

本轮还修正两项确定事实：相同地支不能和自身构成三合；无日期的四柱反查失败后扩窗会跳过已扫描的原月，宿主时区无关的月末日数使用 UTC 日历天数。

阳历日期合法性校验也用 UTC 日历字段，避免宿主时区把月末日期滚入次月；`TZ=Pacific/Kiritimati` 下 1994-12-31 阳历输入 UI 回归已实际通过。扫描月末日数与输入合法性校验是两个独立入口，都必须保持 UTC 语义。

符号表与唯一计数口径在 [elements.ts](../../client/src/features/chart/elements.ts)：`STEMS`、`BRANCHES`、`ELEMENTS`、`HIDDEN_STEMS`（地支本气取藏干首位）、`ELEMENT_RULE_VERSION = 'branch-main-v2'`、`countElements`。该文件同时把中文闸门的几个函数转出给全站使用，见 [13](./13-跨端共享与三端一致性.md)。

神煞逐柱规则表在 [shenSha.ts](../../client/src/features/chart/shenSha.ts)（`computeShenSha`）。真太阳时的经纬度树在 [trueSolarData.generated.json](../../client/src/features/chart/trueSolarData.generated.json)，由 [scripts/gen-true-solar.mjs](../../scripts/gen-true-solar.mjs) 从 DataV 行政区划质心生成、懒加载 92KB 分包，别手改，见 [42-工具脚本](./42-工具脚本.md)。

无人工生肖时按**年柱地支**现算；详情有人工值时读取有效 zodiac。默认生肖通过（[interpersonal.ts](../../client/src/utils/interpersonal.ts) 的 `zodiacOfBranch`），不用库里按春节切分的实现；立春前后出生的差异在详情页与记录列表都会被覆盖掉假值。

大运的**排法方向**（阳男阴女顺排、阴男阳女逆行，以**年干**阴阳定，不是日干）由 [nonAiCalculator.ts](../../client/src/features/chart/nonAiCalculator.ts) 的 `fortuneDirection` 判定，它同时决定九步运干支的走向与起运推算的入参。这一句读数此前只存在于引擎里、界面上从来没有（#150）

详情页的非 AI 可见值通过“编辑数据”在原位置修改，删除旧“修正四柱”弹窗。保存与取消由 [NonAiInlineEditor.tsx](../../client/src/features/person/NonAiInlineEditor.tsx) 的专用控件协助；[PersonDetail.tsx](../../client/src/features/person/PersonDetail.tsx) 只把变动源与触碰的逐叶字段交给 `saveNonAiEdits(recordId, request)`。保存失败保留草稿和中文错误；取消丢弃草稿。姓名、性别、出生年月和公历日期、四柱、五行计数与百分比、四列长生/藏干/藏干十神/十神/纳音、起运跨度与日期、称骨总重与分重、九步大运可见列、生肖与四组适配、七组关系均有原位控件。称骨输入单位为两，步长一钱；比例输入单位为百分比，存储仍为零至一。

基本信息与矩阵四柱、说明月柱/年支共用同一源草稿，出生年月与日期同步；两处本命生肖、每步起运年与区间起点也共用草稿。藏干十神增删后按本、中、余顺序重建 position。人工方向只标顺排或逆排和“已手动修改”，不附默认阴阳原因。展示态保留中文读数，不添加独立日主或未展示的算法表。

改四柱、性别或出生日期由仓储重算未人工修改项并保留人工叶子；源四柱与日期不兼容时整次拒绝。数据层负责真实生日、精确出生时刻与事实修订号，见 [12-客户端-数据层](./12-客户端-数据层.md)。点击“重新排盘”调用 `recalculateBaziRecord`，按钮旁提前说明清除人工值、以当前源恢复自动计算。当前大运标记和起运摘要仍投影真实已保存区间。

批断运行时须先停止才能编辑；编辑及保存期间禁止新批断、清结果和自动重试，并取消已排期重试。AI 写入统一调用 `saveAiProgress`，按启动时事实修订号合入最新记录；停止后的旧进度回调不继续写入。事实变化后本地预览随修订号重挂载，重新生成时读取有效事实。新建排盘的 BirthInputModal 和 ChartPage 输入法逻辑保持原样。

本轮按用户要求停止测试；原位编辑的最终完整回归与真实浏览器输入法/剪贴板验收尚未完成，不能引用前五项通过数字作为本项通过证据。

四柱输入框是受控输入：composition 期间显示浏览器给出的完整预编辑值，compositionEnd 后才过滤干支并把整串截为八个合法字；单柱确认仍只留一干一支并清空整串栏。输入框不设原生 `maxLength`，避免浏览器先截掉拼音或带分隔符的粘贴。composition 期间的 Enter 不触发表单提交，组件不阻止默认键盘事件，让输入法完成候选确认；正常点击提交仍走原校验。`birth-input-modal.test.tsx`、`chart-page.test.tsx` 的既有 DOM 回归覆盖候选草稿、分次手录和关闭弹窗时清理组合状态；详情四柱原位输入不实时过滤或截断预编辑草稿；这些 jsdom 事件用例不代表真实设备或浏览器输入法验收。

## 恢复的本机批断入口

设置页提供独立的本地系统密钥框；开通、启用、停用、收起只写本机标记，不覆盖三条云端凭据。已开通设备可用裸链或 `#cloud` 进入云端，用 `#local` 进入本机规则引擎；App 挂载和地址栏锚点变化统一应用模式，接管成功清掉锚点。详情页订阅同一份状态，每轮启动冻结实际来源；中途改开关影响下一轮。本地预览动态加载引擎，展示本命、十年总结、后天调整，清洗后的同一份正文用于显示和复制。

实际入口为 SettingsPage、App 与 PersonDetail；行为回归见 [local-system-entry.test.tsx](../../client/src/__tests__/local-system-entry.test.tsx) 和 [local-system-design.test.tsx](../../client/src/__tests__/local-system-design.test.tsx)。本地预览不覆盖已保存的云端任务，也不新增本地聊天。

## 逐条点评

详情页由 [ScopeNoteBox.tsx](../../client/src/features/person/ScopeNoteBox.tsx) 在每条有正文的已完成批断旁提供点评入口，覆盖本命、流年、流月、大运、后天调整与全盘总结等完成槽位。用户可新增、保存、取消、修改或删除点评；这项公开的本机功能不受本地系统解锁限制。点评展示经过现有中文清洗流程，且不进入命盘正文或复制内容；数据隔离与删除清理契约见 [12-客户端-数据层](./12-客户端-数据层.md#逐条点评存储)。

## 批断序号与日主展示

详情页的云端旧批断、范围任务和本地结果共用 PersonDetail 内的逐点格式化：已带序号的正文保持原文，未编号点由屏幕显式输出一次中文序号，复制文本复用同一编号语义。point-list 不再用 CSS 计数伪元素，避免正文序号与视觉序号叠加；聊天回答和点评仍按各自原文展示，不套用批断列表格式。详情基础排盘数据不单列“日主”，记录卡摘要只保留公历与生肖；十神中的日主读数及存储、计算事实保持不变。DOM 回归不能渲染 CSS 伪元素，因此另有样式源码判据；本次没有声称浏览器视觉验收。
