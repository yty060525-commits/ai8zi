# AI 命理分析系统：客户端前端阶段规格

## [S1] 项目边界

本阶段只实现单体本地工具的前端，不拆分客户端/服务端，不考虑公网服务器。最终交付形态是 Tauri 独立应用窗口，不是浏览器网页；Vite 浏览器地址只作为开发调试预览。用户未提供数据时生产界面必须为空，不得展示假人物、假运势或假额度。后续 SQLite、非 AI 计算和 DeepSeek 调用作为同一工具内的本地模块逐步加入。

工程与文档分离：规划、规格、报告放在 `docs/compose/`；工具工程放在 `client/`；不得创建或恢复客户端/服务端双工程。

## [S2] 导航与默认页面

界面采用类似微信的底部双分类导航：`排盘`、`记录`。应用启动默认显示排盘分类，内容直接占据主体区域，不设置额外的营销首页、Banner 或 Dashboard。

所有视觉呈现只使用黑、白、灰、线条、文字、字号、字重和间距。禁止彩色主题、渐变、插画、装饰图标、商业卡片和非数据装饰。全部文本保持可选择和复制。

## [S3] 排盘页

排盘页包含：姓名输入、分类选择（客户/亲戚/朋友）、男女按钮开关、剩余额度和费用展示位，以及三种出生信息模式按钮：公历、农历、八字。

点击任一模式按钮，打开对应的弹窗输入表单：

- 公历：年、月、日、时、分、出生地区。
- 农历：年、月、日、时辰、闰月、出生地区。
- 八字：年柱、月柱、日柱、时柱。

本阶段提交后只模拟创建排盘任务，并展示 queued/running/completed/failed 等状态、进度百分比、当前步骤和错误提示。不得假装调用真实计算服务。

## [S4] 记录页与人物详情

记录页使用 mock 人物数据，支持全部/客户/亲戚/朋友筛选、姓名搜索、姓名首字母排序。移动端采用列表；桌面端采用数据网格。性别必须同时显示文字，视觉区分仅使用明度或实线/虚线边框。

人物详情包含四个数据区域：基础信息、行动改变、运势、提问。第一阶段实现结构化展示壳、长文本展示、返回操作及复制本段/复制本年/复制全部按钮。行动改变使用 mock 规则结果展示，不实现真实规则计算。运势按大运、年份、月份懒展开，不一次渲染全部流月长文本。提问只实现绑定当前人物的输入和 mock 回复展示，不接 AI。

## [S5] 数据与接口约束

前端建立类型化 mock 数据模型和数据适配层，至少覆盖 Person、BirthInput、ChartJob、NatalSummary、Fortune、ActionAdvice、AgentMessage、Quota。页面只能通过适配层读取数据，不能把未来 SQL 或 HTTP 细节写进页面组件。

额度与费用本阶段不显示假数字；显示“DeepSeek 额度未连接”。后续由本地 DeepSeek 账户模块读取真实余额/用量，预计消耗根据本地历史实际消耗记录计算。

## [S6] 验收标准

1. 启动后默认进入排盘内容，底部可切换排盘/记录。
2. 男女开关可切换且有文字可读状态。
3. 三种出生模式分别通过按钮打开独立弹窗。
4. 排盘表单可完成本地 mock 提交并看到进度状态。
5. 记录页可筛选、搜索、按首字母排序并打开人物详情。
6. 人物详情四个区域可查看，运势数据支持逐层展开。
7. 页面上的数据和长文本可选择复制，复制按钮可工作。
8. 额度费用有明确展示位但无真实计费行为。
9. 无真实后端、算法、SQL、DeepSeek 请求。
10. 客户端代码与 `docs/compose/`、未来 `server/` 保持目录隔离。
