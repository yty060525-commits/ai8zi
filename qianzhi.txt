# 1. 产品定义

## 1.1 产品目标

开发一套以八字命理数据计算、AI 命理解读、长期运势生成、人物档案管理以及基于人物完整命理数据库进行 AI 提问为核心的软件。

用户输入一个人物的出生信息后，系统自动完成：

1. 出生信息标准化。
2. 八字排盘。
3. 五行计算。
4. 十神计算。
5. 地支藏干计算。
6. 神煞计算。
7. 十二长生计算。
8. 纳音计算。
9. 三合、六合等关系计算。
10. 袁天罡称骨计算。
11. 身强身弱等综合判断。
12. 五行喜忌分析。
13. 行业、行为等适配信息生成。
14. 十年大运生成。
15. 每年流年生成。
16. 每月流月生成。
17. 健康、事业、财运、爱情等维度的 AI 分析。
18. 全部结果持久化进入 SQL 数据库。
19. 客户端同步人物数据库。
20. 用户可以针对任意人物继续通过 Agent 提问。

产品不是商业内容平台，不追求营销式 UI、插画、渐变、卡片美化等。

产品的主要任务是：

**尽可能清晰、高密度、高效率地呈现结构化数据和长文本。**

# 2. 核心工程原则

## 2.1 确定性计算与 AI 必须分离

不建议让 AI 直接“计算”以下可以通过程序确定的数据：

* 八字
* 天干
* 地支
* 十神
* 地支藏干
* 五行数量
* 五行比例
* 纳音
* 三合
* 六合
* 相冲
* 相刑
* 相害
* 神煞
* 十二长生
* 大运起运时间
* 大运干支
* 流年干支
* 流月干支
* 袁天罡称骨
* 生肖

以上内容应该由服务器命理计算引擎确定。

AI 负责：

* 身强身弱综合解释
* 五行喜忌综合解释
* 格局趋势解释
* 适合行业
* 行为建议
* 健康趋势解释
* 财运趋势解释
* 事业趋势解释
* 感情趋势解释
* 大运解释
* 流年解释
* 流月解释
* 人物问题 Agent

原则：

**程序负责事实，AI 负责解释。**

避免由于 LLM 幻觉导致八字、十神、藏干等基础数据发生错误。

# 5. 客户端与数据库关系

客户端不得直接连接服务器 PostgreSQL/MySQL。

正确结构：

```text
Server SQL
    ↓
Sync API
    ↓
Client SQLite
```

客户端维护本地 SQLite 数据库。

好处：

* 查询速度快
* 记录页面即时打开
* 可以离线查看
* 不需要每次切换页面请求服务器
* 降低服务器压力
* Windows/Linux/移动端逻辑一致

服务器数据库为：

**Source of Truth。**

客户端 SQLite 为：

**同步副本 + 本地缓存。**

# 28. API 调用数量优化

如果一个人物生成：

```text
80 年
×
12 月
```

单纯每月调用一次 AI 即：

```text
960 次 API
```

再加：

```text
80 次流年
8 次左右大运
基础分析
```

单人物可能超过：

```text
1000 次 AI 请求
```

这会造成：

* 排盘极慢
* 成本高
* API 限流
* 大量失败任务
* 数据风格不一致

因此推荐支持两种模式。

## 标准模式

一个年份调用一次 AI，同时输出：

```text
年度分析
+
12个月分析
```

约：

```text
80 次 API
```

即可生成全部 960 个月的数据。

## 精细模式

每个月单独调用一次 AI。

作为可配置高级计算模式。

第一版本推荐默认采用：

**标准模式。**


然后发送 AI。

降低：

* Token 消耗
* 无关信息
* AI 注意力污染

# 71. 隐私与安全

* API Authentication

# 72. 健康与财运内容边界

健康运势属于命理解读，不应表现为医学诊断。

禁止生成：

```text
你明年一定得某种疾病。
```

应表现为：

```text
从命理解读角度，这一阶段可以更关注休息、压力和身体状态；具体健康问题应以专业医疗检查为准。
```

财运同理。

不得将命理解读直接包装成确定性投资建议。

系统定位为：

**命理信息与趋势解释工具。**

# 81. 第一版验收标准

一个完整测试人物必须能够完成以下流程：

1. 用户输入公历、农历或八字中的任意一种。
2. 系统成功创建人物。
3. 后台启动排盘任务。
4. 客户端实时显示处理进度。

# 82. 产品核心结论

这款软件不应该按照传统“AI App”思路开发。

它应该被定义为：

**命理计算数据库 + AI 批处理系统 + 本地数据浏览器 + 人物 Agent。**

系统四层分别为：

```text
第一层
确定性命理计算

第二层
结构化人物数据库

第三层
批量 AI 运势生成

第四层
客户端数据查看与 Agent
```

前端不承担命理核心。

AI 不承担确定性算法。

SQL 是整个系统的中心。

客户端主要负责：

**查数据、组合数据、展示数据、复制数据。**

服务器主要负责：

**算数据、生成数据、保存数据、检索数据。**

这应作为整个项目后续开发过程中不可改变的核心架构原则。
